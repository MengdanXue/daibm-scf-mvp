# Сценарий демонстрации / 答辩演示讲稿

Продолжительность: около 4 минут. Интерфейс по умолчанию открывается на русском языке; кнопка `中文` позволяет мгновенно перейти к китайской версии.

建议用时约 4 分钟。页面默认使用俄语，右上角 `中文` 可以即时切换中文版本。

## 0. Ролевой бизнес-процесс / 五角色业务流程（约 3 分钟）

Все демонстрационные роли используют пароль `Demo123!` / 所有演示角色使用密码 `Demo123!`：

1. Войдите как `supplier.demo`, заполните форму, сохраните черновик и нажмите **«Подать заявку»**. / 使用 `supplier.demo` 创建草稿并提交。
2. Выйдите и войдите как `core.demo`; откройте заявку, укажите подтверждаемый предел задолженности (не ниже суммы счёта), добавьте комментарий и нажмите **«Подтвердить сделку»**. / 使用 `core.demo` 确认合同与发票，并录入不低于发票金额的应付上限。
   Если запущен расширенный режим, подтверждение сопровождается доказательством с нулевым разглашением «счёт не превышает предел»: в карточке появляются схема, хеш доказательства и обязательство к сумме, а сама сумма счёта в доказательство не входит. Без расширенного режима подтверждение проходит, а событие фиксирует причину отсутствия доказательства. / 若启用高级模式，确认会附带“发票金额不超过应付上限”的零知识证明：详情页显示电路、证明哈希与金额承诺，而发票金额本身不进入证明。未启用时确认照常完成，事件中记录未附证明的原因。
3. Войдите как `financier.demo`; сначала выполните **«Оценку риска»**, затем выберите решение. / 使用 `financier.demo` 执行风险评估并作出融资决策。
4. Войдите как `risk.demo` и зафиксируйте контрольное действие. / 使用 `risk.demo` 设置控制措施。
5. Войдите как `auditor.demo`, проверьте историю передачи и завершите аудит. / 使用 `auditor.demo` 检查完整交接历史并完成审计。

В карточке заявки покажите два доказательства: отпечаток торговых реквизитов и версию бизнес-оценки с хешем входа. Отпечаток относится только к введённым полям и не выдается за криптографическую проверку исходного файла. / 在申请详情中展示交易字段指纹和业务评分版本/输入哈希；字段指纹仅验证已录入内容，不声称完成原始文件真实性认证。

> Это не имитация переключения ролей: каждая учётная запись создаёт отдельную серверную сессию, а недопустимые переходы блокируются API. Версия заявки увеличивается после каждого действия, переход и событие журнала записываются одной транзакцией.

中文说明：这不是前端模拟切换。每个账户都建立独立服务端会话，API 会拒绝越权或过期版本；每次操作都会同时更新申请版本、业务状态和审计事件。

### 0.2. Опциональное якорение Fabric / 可选 Fabric 锚定（60 секунд）

Для расширенной демонстрации заранее запустите `start-fabric-demo.cmd`. После завершения пяти ролей аудитор открывает **«Аудиторский реестр»**, нажимает обновление и показывает реальные счётчики `pending`, retry, `anchored` и `permanent_failed`. Нажмите **«Отправить одну партию»**: интерфейс выводит фактическую сводку API, а не рисует успех. Повтор вручную доступен только для `permanent_failed`. Gateway доступен приложению лишь во внутренней Docker-сети и не имеет host port.

高级演示前运行 `start-fabric-demo.cmd`。五角色流程完成后，审计员打开“审计账本”，刷新并展示真实的 `pending`、待重试、`anchored` 与 `permanent_failed` 计数。点击“派发一批”后，页面只呈现 API 的实际结果，不伪造成功；只有 `permanent_failed` 可手动重新入队。Gateway 仅存在于 Docker 内部网络，不暴露宿主机端口。

Если Fabric недоступен, покажите прозрачную деградацию: бизнес-процесс продолжает фиксироваться в PostgreSQL, а хеш остаётся в outbox. Для осознанной очистки только Fabric выполните `start-fabric-demo.cmd /clean` и введите точно `RESET FABRIC`; PostgreSQL сохраняется. / Fabric 不可用时，业务仍写入 PostgreSQL，哈希继续在 outbox 积压。仅需清理 Fabric 时运行 `start-fabric-demo.cmd /clean` 并准确输入 `RESET FABRIC`；PostgreSQL 数据保留。

### 0.1. Финансовый цикл после аудита / 审计后融资生命周期（可选 90 秒）

1. Войдите как `financier.demo`, откройте **«Финансирование»**, укажите ID одобренной и прошедшей аудит заявки и разделите основную сумму на два точных транша. / 融资方在“融资”页引用已批准且已审计的申请，将本金精确拆成两期。
2. Нажмите **«Инициировать выдачу»** и **«Подтвердить выдачу»**; покажите идентификатор и хеш синтетического свидетельства. / 发起并确认模拟放款，展示参考号和证据哈希。
3. Войдите как `supplier.demo`, поочерёдно подайте два платежа; после каждого вернитесь к `financier.demo` и подтвердите его. / 供应商提交两笔还款，融资方分别确认。
4. Войдите как `auditor.demo`, закройте полностью погашенный объект, проверьте цепочку журнала и переключите интерфейс на китайский. / 审计员结清零余额融资，验证账本后切换中文。

> This is a controlled financing lifecycle simulation. It does not execute a real bank transfer. Interest, fees, FX, accounting entries, external settlement, and reconciliation are not implemented. / 这是受控的融资生命周期模拟，不执行真实银行转账；利息、费用、汇兑、会计分录、外部结算与对账均未实现。

### 0.3. Контролируемый фактический результат / 受控结果回流（可选 60 秒）

Boundary: gated automatic activation of the Platt business-baseline calibration only; fitting-sample metrics are not held-out validation.

После закрытия объекта останьтесь под `auditor.demo`. В карточке закрытого финансирования заполните факт дефолта, дни просрочки, убыток, время наблюдения, provenance `CONTROLLED_DEMO` и понятную ссылку на свидетельство. Браузер сам вычисляет SHA-256; исходная ссылка не отправляется. При сетевом повторе сохраняется тот же idempotency key. / 结清后继续使用 `auditor.demo`，在融资详情录入是否违约、逾期天数、损失额、观察时间、`CONTROLLED_DEMO` 来源和证据引用。浏览器本地计算 SHA-256，原始引用不会发送；网络重试复用同一幂等键。

После отправки покажите immutable outcome lineage, статус запуска, число положительных/отрицательных наблюдений, Brier/log loss до и после и artifact integrity. Кандидат Platt может автоматически активироваться только для бизнес-baseline после прохождения gate; иначе сохраняется отказ или fallback. Контур не переобучает TGNN и не запускается по дрейфу. Brier/log loss рассчитаны на обучающих наблюдениях, не на независимой выборке; улучшение на реальных предприятиях не доказано. / 提交后展示不可变 outcome lineage、运行状态、正负样本数、校准前后 Brier/log loss 与工件完整性。Platt 校准候选通过 gate 后可自动激活，但只作用于业务 baseline；不满足条件则拒绝或回退。不重训 TGNN、不由漂移触发；Brier/log loss 使用拟合样本，不是独立留出评估，也不证明真实企业效果。

## 2. Исследовательское ядро / 科研核心（80 секунд）

Откройте **«Исследовательское ядро»**. Сначала покажите пять связанных карточек: данные, временной граф, модель, политика и аудиторский след.

Шестая карточка показывает проверенные метрики повторной реализации: ROC-AUC TGNN и XGBoost. Маркировка `2026_REIMPLEMENTATION` означает, что это показатели синтетического повторного запуска, а не исходные показатели диссертации. / 第六张卡展示经工件校验的 TGNN 与 XGBoost 重实现 ROC-AUC；`2026_REIMPLEMENTATION` 明确表示它们不是论文原始实验指标。

**Русский текст**

> Здесь показана не статичная презентация, а воспроизводимая трасса решения. Система использует детерминированные синтетические данные 500 предприятий за 24 месяца, строит 12-месячное графовое окно и выполняет реальную инференцию минимальной GCN–BiLSTM TGNN через ONNX Runtime. Версии данных, модели и политики связаны хешами, а результат фиксируется в PostgreSQL.

Для предприятия `E0001` нажмите **«Выполнить инференцию»**. Базовый результат эталонного артефакта — примерно `0.5623`, политика **ADDITIONAL_CHECK**.

Затем нажмите **«Ввести риск-сценарий»**. Интерфейс покажет изменённые наблюдаемые признаки, связанные предприятия и новый результат примерно `0.7519`, который переводит решение в **FINANCING_REVIEW**. Подчеркните: сценарий меняет только версионные синтетические входы; оценка не задаётся вручную, граф перестраивается, а та же модель выполняет инференцию повторно.

**中文提示**

进入**“科研核心”**，先展示“数据—时序图—模型—策略—审计”五段证据链。对 `E0001` 点击**“执行模型推理”**，参考结果约为 `0.5623`，进入追加核验。随后点击**“注入风险场景”**，页面会显示实际变化的输入、关联企业和重新推理后的约 `0.7519`，策略转为融资审查。要明确：系统没有直接填写风险分数，而是修改版本化合成输入、重建图并再次执行同一个 ONNX 模型。

## Резервный вариант / 答辩备用方案

### ZKP: проверка готовности / ZKP 验收边界

默认 `ZKP_PROOF_REQUIRED=false` 保持双容器演示可用；证明服务不可用时记录 fallback。
如要演示必需证明模式，在项目 `.env` 设置 `ZKP_PROOF_REQUIRED=true` 后重新创建应用容器；未取得可用证明时交易确认返回 HTTP 503，状态、版本、确认金额和审计记录整体回滚。
这要求来自可信内部 prover 的证据，不等于 Python 或 Fabric 已独立验签。

运行 `start-fabric-demo.cmd` 启动可选服务后，在项目根目录执行：

```powershell
docker compose -f advanced/fabric/network/docker-compose.fabric.yml --project-name daibm-fabric-demo exec -T zkp-prover node src/preflight.mjs
```

该预检先检查健康端点，再请求固定合成命题 `1 <= 2` 的真实证明，并使用已校验工件哈希的本地验证密钥执行 Groth16 验证。不写业务数据库，不把健康端点的 ready 当作证明有效。
退出码必须为 0，输出必须为 `SYNTHETIC_PREFLIGHT` 和 `proof_verified: true`。
CI 中 `tests/test_invoice_proof_integration.py` 进一步检验真实 HTTP prover → 交易确认 → PostgreSQL 审计事件 → 离线验证，并拒绝被改动的 public signal；它不启动完整 Fabric 网络，也不证明生产级安全性。

В обязательном режиме отсутствие пригодного свидетельства блокирует подтверждение (HTTP 503) с откатом транзакции. Предпроверка проверяет реальное синтетическое доказательство, но не весь Fabric-контур. Python доверяет внутреннему prover; якорение хеша не является проверкой Groth16.

Если сеть недоступна, система продолжает работать локально: контейнеры FastAPI, PostgreSQL и веб-интерфейс не требуют внешнего API. Перед выступлением запустите `start-demo.cmd`, дождитесь сообщения о готовности и один раз создайте тестовую заявку.

如果现场没有网络，FastAPI、PostgreSQL 和页面容器仍可完全本地运行，不依赖外部 API。建议答辩前运行 `start-demo.cmd`，等待健康检查通过，并创建一笔测试申请确认流程正常。

Перед выходом выполните только читающую проверку `.\.venv\Scripts\python.exe scripts\defense_preflight.py`. Для намеренно чистого локального сброса используйте только `reset-defense-demo.cmd` и точное подтверждение `RESET DEMO`. / 上场前运行只读预检 `.\.venv\Scripts\python.exe scripts\defense_preflight.py`。如确需全新本地重置，只运行 `reset-defense-demo.cmd` 并准确输入 `RESET DEMO`。

Если браузер недоступен, откройте `docs/defense-one-page.pdf` и `docs/research-brief-en.pdf`; затем при необходимости покажите `output/five-role-acceptance.png`, `output/defense-video/*.webm` и `output/research/sensitivity-pack/`. / 如果浏览器不可用，打开 `docs/defense-one-page.pdf` 与 `docs/research-brief-en.pdf`，并按需展示截图、可选视频和五种子科研证据包。
